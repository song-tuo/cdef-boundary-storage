# Finite-frame capacity and hybrid realization

R is the number of 64x64 filter-block rows. W is the number of CDEF workers assigned to this frame, not the number currently busy on a particular instant. A worker executes one row at a time. Dispatch issues rows monotonically under the existing job mutex. For non-final row r, dispatch reserves outgoing top T_(r+1) and own bottom B_r. Both boundary copies occur before row r signals copy readiness; filtering waits for predecessor copy readiness. T_r and B_r remain live until row r's filter returns. T_(r+1) is not released by producer r.

At any point the live top consumers are the positive-index active rows, plus at most the single not-yet-issued chain tail. There are therefore at most min(R-1,W+1) tops. Each live bottom belongs to a non-final active row, so there are at most min(R-1,W) bottoms. Their sum is min(2R-2,2W+1): when R-1<=W both terms are R-1; otherwise the terms are W+1 and W. Legal schedules can attain the two maxima simultaneously. The independently rerun finite checker retains a witness for every R=1..10,W=1..4 case and checks the combined maximum, not only separate maxima. The general contract argument, rather than finite enumeration alone, supports arbitrary R,W.

For R-1>=W, map each bottom to its executing worker's persistent slot. The worker cannot issue another row until its current filter returns and release bookkeeping completes; hence two simultaneously live bottoms cannot share that slot. For R-1<W, map each non-final row r directly to slot r; ordered one-time dispatch makes this injective, and the final row owns no bottom. Neither branch needs bottom ownership state, a free-slot search or capacity waiting. The diagnostic builds check active-row collisions independently; that shadow state is not part of the implementation or timing/allocation measurements.

Tops retain the existing dynamic first-free allocation under the job mutex. Exhaustion is an invariant failure, not a wait. Active rows' incoming tops plus the one tail prove that the prescribed capacity suffices without modifying issue order or copy/filter sequencing. Error paths use the upstream worker-local longjmp and readiness wakeup; normal liveness does not prove error-path safety. Fault/recovery and sanitizer evidence are required independently.

The formulas concern boundary strips for the row-MT realization. They do not include metadata, colbuf/srcbuf or allocator padding. A zero-boundary one-row MT case retains the existing one-unused-sample sentinel; it is reported separately from strip capacity. The W=1 legacy serial implementation is a compatibility control, not an implementation-capacity PASS: its untouched ping-pong allocation is separately disclosed.
