# Historical scope, failures and controls

The complete v3.12.1 study was run on macOS 26.6.2 / Apple M5 Pro / 48 GiB / Apple Clang 21.0.0. This public package recalculates the published memory and timing tables and provides new core build/check helpers. It is not a self-contained executable replay of every historical engineering test or an independent implementation, team or host replication.

The three original release variants passed 540 normal decoder processes; token Debug, ASan+UBSan and TSan each covered 180 generated configurations. The upstream conformance group contained 3,899 cases in each of three release variants and two sanitizer profiles. Those are test-case counts, not independent content samples. The libaom archive had 286 instrumented object members in the sanitizer profiles; this does not establish all-path execution coverage.

The tile/row-MT group had 508 unique cases. Eighty failed in an initial attempt and were rerun after input preparation, giving 588 attempts; the original XML and retry records remain. Missing input was a plausible explanation, not a formally isolated root cause. Broad ASan core/row-tile and TSan encoder stress work was interrupted and is not counted as passing. Three upstream disabled resize cases and unsupported SVE CPU paths were not run.

Fault campaigns retained 156 ASan and 156 TSan cases each (132 injected faults plus 24 controls), with separate clean fresh-process decodes afterward. Same-instance keyframe recovery covered 99 cases per sanitizer profile. The exported historical fault runner is not asserted to be the exact byte-locked runner for every older fault log; the timing runner has a stronger explicit byte lock. Full fault/sanitizer replay requires source instrumentation, media, toolchain and orchestration beyond the portable smoke helper.

macOS LeakSanitizer was unavailable. Native `leaks` reported zero for 36 checks while also issuing process-access warnings. A deliberately lost 31,337-byte allocation was reported as a 32,768-byte root leak in the successful positive probe; an earlier probe did not establish detection. These are bounded observations, not a general proof of leak absence.

The original synthetic primary timing retained 216 analyzed pairs plus 72 large-delay control pairs and 24 warmup pairs. All 18 original primary screens passed their frozen rule. A later adjacent-two-pair block diagnostic gives an upper interval of 1.022851364 for texture/1080p/W16, crossing 1.02; the original PASS is retained and the later diagnostic is explicitly post hoc. The recalculation writes both analyses separately. The six sensitivity controls injected 82 ms per packet inside the harness timer after the decode call. The dose was selected before confirmation using the maximum per-packet time across pilots **and final streams**; it was not held-out calibration and establishes neither 2% power nor a source-internal CDEF delay trace.

Original peak RSS used one process per fixed-order memory cell. It gives system context, not a replicated causal RSS effect. At 1080p/W16 the requested boundary bytes decrease while allocator-usable capacity remains 512 KiB.

Natural content was a separate prospectively frozen supplement: three UVG scenes, six encoded streams, 12 configurations, all with 60/60 CDEF-stage entries. Its 312 pairs comprise 288 analyzed pairs and 24 warmups. All 624 timing processes and 72 audit/correctness processes completed without measured-run replacement or exclusion. The first timing launch stopped at a denied process-snapshot call **before any measurement**; the unchanged script then ran with permission, and the original traceback is exported. One proposed geometry assertion was restored to the locked runner bytes before any decoder process; the retained preparation note records this. Desktop background services remained active, and only competing project builds/encodes were paused.

The natural pointwise 95% intervals all satisfy the frozen 1.02 upper-endpoint screen. They are not simultaneous confidence bands or a universal cross-platform speed guarantee. Six streams are derived from three 0.5-second scenes, not six independent natural scenes.

v3.15.1 and the September 30 pinned main received bounded source/build/correctness/conformance/allocation checks, not the full frozen campaign. The October 1 upstream report additionally compares the two relevant source files at its newly recorded main commit. It does not retroactively extend the earlier binary tests to that newer commit.
